# 默契找茬局 · 验证记录

日期：2026-11-23。当前为本地演示模式，没有真实微信 AppID、云环境和 BesChannels 接口。

## 已完成

- 27 项业务、原生页面模拟和视觉算法检查通过。
- 在 99 个随机种子 × 3 档难度，共 297 个关卡中，比对真实栅格像素，AI 提示能够依次定位全部 5 个差异；相同图片不会报告差异。
- 找茬计分、错误点击、重复点击、提示上限、时间边界、100 次事件自动终局、发现顺序重放与分享参数校验通过。
- 云端同关邀请、身份隔离、服务端结果与时间校验、首触归因、领取并发、咨询授权、队列重试及撤回检查通过。
- 好友挑战完成后，双方可以从本人记录读取最多最近 10 张合拍卡；重复提交不重复写入。对方身份和手机号不会出现在卡片里。
- 原生页面与本地演示的跳转、记录恢复、虚拟咨询、无静默回退、组件及事件绑定检查通过。
- 28 个 JS/CJS 文件、20 个 JSON 文件静态检查通过；客户端与云端找茬规则一致。

浏览器验证使用两个相互隔离的玩家环境：A 找完并分享链接，B 打开相同图片与难度，按不同顺序找完后，界面结果与规则计算一致。覆盖 AI 提示、点错反馈、小礼物领取、虚拟品牌申请、营销撤回与刷新后的记录恢复。手机宽度 320/390 和电脑手机框布局已检查；使用浏览器时钟前进验证了 60 秒结束时自动结算，零发现也能正常结束。

## 如何复现

```bash
# wechat-miniprogram 目录，Node.js 18+
npm test
npm run check
npm run check:release

# 完整仓库根目录
node phone-demo/build.cjs --check
# 安装 Playwright，并在本机 8771 提供静态文件服务后
node tests/phone-preview.test.cjs
```

发布检查在占位 AppID、demo 模式和空 cloudEnv 下应拒绝通过。自动化流程文件作为示例提供；现有仓库令牌缺少工作流写入权限，未启用自动 CI。
