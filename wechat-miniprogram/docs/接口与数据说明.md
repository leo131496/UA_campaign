# 接口与数据说明

## 信任边界

前端仅调用 `campaign` 云函数。用户身份取自 `cloud.getWXContext().OPENID`，不接受客户端传入的 `owner/openid/tenantId/inviter/score/phone` 作为事实。活动归属由服务端 `ua_campaigns` 确定。手机号只由微信一次性 `code` 在服务端换取。

数据库客户端读写均关闭。`campaign` 处理业务写入，`scrm-dispatch` 由服务端定时触发。同步函数拒绝带客户端 OPENID 的调用；部署时另限制其调用权限为服务端定时器与受控管理员。云环境及其管理密钥只交给可信运维人员。

## 小程序云调用协议

```js
wx.cloud.callFunction({
  name: 'campaign',
  data: { action: 'visitCampaign', payload: { campaignId: 'project-rescue-2026', inviteToken: '' } }
})
```

成功：`{ ok: true, data: ... }`。业务失败：`{ ok: false, code, message }`。未知服务异常返回通用错误，不向客户端输出堆栈或原始微信接口响应。

| action | 输入 | 输出 / 约束 |
| --- | --- | --- |
| `visitCampaign` | `campaignId`, 可选 `inviteToken` | 公开活动配置；首次到访及邀请来源。有效邀请码可解析到其绑定活动 |
| `startChallenge` | `campaignId`, `requestId` | `sessionId/seed/expiresAt`；同一请求幂等，默认每天最多 30 局，有效两小时 |
| `finishChallenge` | `sessionId`, `moves:[{card,target}]` | 服务端验证结果；最多 12 步、必须终局、必须本人；重复同记录返回原结果 |
| `claimBenefit` | `campaignId`, `sessionId` | 资料内容和领取记录；每活动每用户一次；无需胜利、邀请或手机号 |
| `createInvite` | `campaignId` | 24 位随机十六进制 token；仅生成链接，不增加传播人数 |
| `getPromotionStats` | `campaignId` | 本人的 `arrivals/finishes/claims/requests` 四个去重人数 |
| `requestConsultation` | `campaignId/topic/serviceConsent/privacyVersion/phoneCode/marketing/shareRecap`，附复盘时带 `sessionId` | 本人申请与脱敏手机号、同步状态；每活动每人一条；服务授权必需，可选授权必须显式布尔值 |
| `getMyActivity` | `campaignId` | 本人资料、咨询与同步状态；不返回其他参与者信息 |
| `revokeMarketing` | `campaignId` | 撤回本人后续营销，写出撤回事件；咨询服务申请继续有效 |

`pass` 表示提前结束回合，目标填 `0`；其他 `card` 为规则引擎中的六种卡，目标为 `0/1/2`。云端逐步调用与客户端相同的规则引擎，未完成或非法动作拒绝。对同一已完成局提交不同记录返回 `CONFLICT`。

挑战结果以服务端为准。本机 AI 参考分只作为玩法说明，不参与奖励、排行榜或销售评分。重新开始活动不会改变既有首触归因。

手机号申请首先检查幂等记录，再调用微信换号。相同已完成请求重试时不再次消耗一次性 code；同一活动已有申请但内容变更会返回 `DUPLICATE`，引导查看原申请。单个用户恶意高频或多号刷量仍需平台级限流、告警与业务风控，当前不是反作弊平台。

## 数据库

所有时间均为服务端毫秒时间戳。组合主键用 SHA-256 截断生成，不在小程序端计算用户身份。8 个集合见 `database/indexes.json`。

| 集合 | 主键 / 主要内容 |
| --- | --- |
| `ua_campaigns` | 活动 ID；归属租户、品牌、状态、日期、模块、资料、咨询主题、隐私说明、可选客服 |
| `ua_visitors` | hash(活动, OPENID)；本人身份、首次邀请来源、到访时间、是否完成、每日开局数 |
| `ua_sessions` | hash(活动, OPENID, requestId)；随机种子、归属、期限、已验证结果及行动签名 |
| `ua_invites` | 随机 token；所属活动、邀请人、失效时间 |
| `ua_claims` | hash(活动, OPENID)；领取资料快照、领取时间 |
| `ua_leads` | hash(活动, OPENID)；验证后手机号、咨询主题、服务/营销/复盘授权、版本和时间 |
| `ua_stats` | hash(活动, 邀请人或总计)；四项独立人数，不存分享点击次数 |
| `ua_outbox` | `claim_/lead_/revoke_` + 参与者键；事件、状态、尝试次数、下一次时间、处理租约 |

`stock: null` 表示不限量的数字资料；数字表示总领取份数，领取与库存扣减在同一事务中完成。默认资料不涉及现金价值。

数据库权限文件是每个集合的规则内容，不是自动部署脚本。手机号存在受限的 `ua_leads` 和咨询事件队列中，日志不得输出它们。字段级加密、保留期限和清理任务须按项目方数据治理要求补充；当前代码未实现自动清理。上线前必须确定期限和删除渠道，不能保留示例隐私文案。

## SCRM 适配契约

`SCRM_ENDPOINT` **是项目方要提供的 HTTPS 适配服务**，不是已知的 BesChannels 官方 API，也不要填登录页 `/dashboard`。适配服务需根据 BesChannels 实际文档完成鉴权、联系人去重、业务字段映射与分配跟进。

服务端环境变量：

```text
SCRM_ENDPOINT=https://your-adapter.example/ua-events
SCRM_AUTH_TOKEN=配置在云函数中，不提交仓库
SCRM_TENANT_ID=与活动 tenantId 一致
```

一份同步函数配置对应一个租户的适配目标。多个租户需要独立环境/部署或扩展服务端租户路由；当前发送端不从用户输入选择目标地址。

HTTP 请求：`POST`，`Authorization: Bearer ...`，`Idempotency-Key: <eventId>`。

```json
{
  "schemaVersion": "1.0",
  "eventId": "lead_<participant-hash>",
  "tenantId": "your-tenant",
  "campaignId": "project-rescue-2026",
  "type": "consultation.requested",
  "occurredAt": 1795392000000,
  "data": {
    "participantId": "<opaque-hash>",
    "phone": "<server-verified-phone>",
    "topic": "提升团队协作",
    "serviceConsent": true,
    "marketing": false,
    "privacyVersion": "your-published-version",
    "consentAt": 1795392000000,
    "recap": null,
    "attributionId": "<inviter-participant-hash-or-null>"
  }
}
```

接收成功必须同时返回 2xx 和匹配的确认体：

```json
{ "accepted": true, "eventId": "lead_<participant-hash>" }
```

这表示适配服务已持久化接受事件，不表示销售已联系、微信加友成功或成交。适配服务还需保证内部落库/队列可靠；仅接收后丢弃请求不符合契约。

| 事件 | 建议适配处理 |
| --- | --- |
| `benefit.claimed` | 写活动参与记录；仅不透明活动标识、资料名、邀请来源，没有手机号，不默认创建可营销线索 |
| `consultation.requested` | 用验证后手机号匹配现有联系人或新建待跟进联系人，记录主题、授权、活动来源；复盘为空时不得补抓 |
| `consent.revoked` | 将该参与者在本活动的后续营销授权撤回；保留审计。包含 `dependsOn`，必须在对应咨询事件接收后处理 |

`participantId` 是活动级标识，不是微信 UnionID。跨活动/跨应用关联不能凭它猜测同一人。手机号归一化与已有联系人去重由 SCRM 适配服务负责，游戏分数不能映射为购买意向标签。

## 可靠性与故障处理

- 业务记录和待同步事件同一事务写入，保存申请不会依赖外部 SCRM 当下可用性。
- 没有同步配置时保留 `pending`，不假装成功。
- 定时任务每分钟触发，单批最多 5 条，处理租约 60 秒，幂等键不随重试变化。
- 失败按 30 秒起指数退避，上限一小时；第八次失败进入 `dead`。修复后由受控运维将该事件恢复 `retry` 并设 `nextAttemptAt` 为当前时间，不创建新事件 ID。
- 崩溃可能造成重复投递，属于至少一次传输；接收端必须以 eventId 去重。微信云数据库本身的事务冲突由 SDK 重试。
- 撤回授权会更新尚未送达的咨询事件，并发出独立撤回事件；撤回事件不会越过对应咨询事件。适配端按参与者顺序应用授权变化。
- 等待前序咨询的撤回事件会延后检查，避免堵塞整批队列。前序事件进入 `dead` 时，撤回事件也标记 `dead/DEPENDENCY`；人工修复时先恢复咨询事件，再恢复撤回事件。
- 本机“我的资料”仅显示同步状态，不暴露上游错误全文；真实告警、人工处理界面、长期归档与监控需要项目方接入。
