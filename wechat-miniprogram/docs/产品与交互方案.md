# 默契找茬局：客户愿意玩的好友挑战

[打开手机 Demo](https://leo131496.github.io/UA_campaign/spot-preview.html?v=5)

## 设计理念

企业是活动的发起者，客户是来玩的参与者。客户打开后只需要看图、点不同、和朋友比一比。企业的业务流程、项目启动、资源调配和获客看板不出现在游戏里。

把“找不同”的低门槛与“好友默契”的社交动机组合：我先找完 → 邀请朋友玩同一张图 → 对比我们最先注意到的细节 → 生成双人趣味结果 → 朋友再发起自己的挑战。传播理由来自两个人之间的好奇与互动。

品牌在活动署名、小礼物和玩完后的自愿了解入口中出现；SCRM 在服务端承接来源、参与、领取和明确授权后的联系申请。

## 客户实际怎么玩

1. 进入“默契找茬局”，点击“开始找茬”。不填表、不选岗位、不描述业务。
2. 上下两张趣味插画共有 5 处颜色细节不同。60 秒内点击不同之处，两张图都可以点。
3. 找对会出现圈选与勾号；点错扣 5 分。AI 提示先给出一排区域，再给出具体物体，每次扣 15 分，最多 3 次。
4. 找齐自动结算；时间到或主动揭晓也能结束并领取小礼物。
5. 邀请朋友玩同一关。朋友先独立寻找，完成后才在界面揭晓“神同步搭子 / 互补侦探组”等趣味合拍结果。
6. 朋友可以再邀请自己的朋友，把这次游戏体验传播下去。

没有“邀请三个人才能继续”、群转发任务、假进度条或自动加好友。奖励不绑定分享次数。

## AI 能力：现在实际实现了什么

| 能力 | 实现与效果 |
| --- | --- |
| 视觉差异发现 | 将与插画共用的图元栅格化，逐像素比较两张画面，再通过连通区域搜索定位变化。提示不读取预先写死的答案文字 |
| 渐进式帮助 | 排除已找到的区域，先标出一排，再提示某个物体的颜色；不替玩家自动点击 |
| 难度适配 | 根据找到数量、耗时和提示次数推荐下一局难度；难度改变真实差异区域大小。好友对局沿用发起人的难度，确保同关 |

当前运行的是**本地经典视觉算法**，没有调用大语言模型、图像生成模型，也没有上传玩家照片。插画由可复用的矢量图元生成。没有用固定返回文案声称“大模型正在创作”。

合拍百分比是透明的游戏规则，不是 AI 人格测评：双方至少各找到 3 处，比较前三处发现的交集，并给第一眼发现同一物体额外权重。每次结果由实际操作顺序计算。不得据此推断性格、职位或采购意向。

## 为什么愿意分享

分享卡问的是“我们会先发现同一个小细节吗？”，不是“帮我助力”。好友拿到同一张图、有明确的挑战对象，完成后得到与发起人相关的结果，而不是孤立的分数。

在线 Demo 已支持跨浏览器/跨设备链接：链接携带关卡、难度与发起人的发现顺序，第二位玩家完成后能算出双方结果。演示数据由链接自报，没有正式身份校验，不用于真实奖励或拉新统计。

正式云模式使用服务端邀请码绑定已完成的本人游戏，好友拿到服务器确认的相同关卡；终局在服务端重放后计算双人结果。双方可在“我的小礼物”里刷新查看最近的合拍卡，不需要系统自动发消息。浏览器演示仅保留当前设备产生的结果，不模拟跨设备回传通知。邀请码也承担首次来源归因。点击分享不计新增，自己打开和重复到访不计新增。

## B2B 企业如何使用

| 企业负责的事情 | 客户看到的体验 |
| --- | --- |
| 在公众号、展会、客户社群、销售触达中投放活动入口 | 一分钟轻松小游戏 |
| 配置品牌署名和趣味场景 | 自然的品牌露出 |
| 配置客户真正感兴趣的小礼物 | 玩完直接领，不先强制留手机号 |
| 配置资料、产品体验或咨询入口 | 感兴趣再主动了解 |
| SCRM 去重、授权记录、后续跟进 | 只有明确申请后才联系 |

当前示例小礼物为实际可阅读、复制的“双人周末灵感卡”。正式 B2B 活动可替换为样品体验、专业资料、展会权益等真实可履约内容。不能把示例当作已开通的现金券、实物奖励或体验名额。

小游戏帮助扩大活动触达和形成一次轻松的品牌接触。有效商业线索仍取决于投放人群、品牌内容、权益相关性与客户主动兴趣，不能保证玩游戏的人就是企业采购决策者。

## SCRM 结合位置

在 BesChannels 的营销活动中配置活动，不另让客户面对企业管理后台。

- 到访：活动 ID、首次邀请来源、独立访客标识。
- 游戏：开始、完成、找到数量、使用提示；用于活动运营，不映射采购意向。
- 小礼物：独立领取记录。
- 主动了解：用户选择的品牌主题、微信验证手机号、授权版本与时间。未选择附加游戏记录时，不发送游戏复盘。
- 运营：邀请到访、完成、领取、主动申请及 SCRM 去重后的净新联系人。客户页面不展示企业获客漏斗。

目前没有 BesChannels 接口资料与真实微信主体条件，正式系统尚未连接。代码包含发送端、待同步队列和适配契约；管理端配置界面及实际厂商字段映射待对接。

## 手机交互与开发形态

七个微信原生页面：活动、找茬、结果、小礼物、好友邀请、了解品牌、我的小礼物。手机游戏页以两张图片为核心，计时和进度在上方，AI 提示与揭晓在下方。柔和紫色、浅粉和奶黄用于轻松氛围，圈选反馈明确。

在线 Demo 直接复用原生页面和规则，只映射浏览器能支持的交互。它不是微信已发布体验版。微信开发者工具编译、SVG 图片兼容、真机点击、原生分享和手机号授权仍需真实环境验证。

历史“项目急救局”已退出当前产品方向，旧方案仅保存在 archive 中。
