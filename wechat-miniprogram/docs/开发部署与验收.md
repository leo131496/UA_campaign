# 开发部署与验收

## A. 本地导入

交付技术类型：微信 `miniprogram`，无 WebView、无前端框架依赖。导入 `wechat-miniprogram/`，不要导入仓库旧版网页根目录。

`project.config.json` 已声明 `miniprogramRoot` 与 `cloudfunctionRoot`。没有 AppID 时先用开发者工具提供的测试号/本地项目导入方式；默认 `touristappid` 只是占位。以工具当前版本要求为准，必要时新建测试项目并复制源文件。

保留 `miniprogram/config.js` 中 `mode: 'demo'`。从活动页开始运行，页面顶部会明确提示本地演示。数据保存在本机微信存储；清除模拟器缓存可以重置演示。不会上传真实手机号，不生成看似可扫描的假二维码。

## B. 配置真实微信环境

1. 获取企业自己的小程序 AppID、对应开发者权限与可用云开发环境；在工具中绑定环境。云函数运行时选服务支持的 Node.js 18 或更新版本。
2. 替换 `project.config.json` 的 AppID；配置 `miniprogram/config.js` 的 `mode: 'cloud'`、`cloudEnv` 和默认活动 ID。
3. 创建 `database/indexes.json` 列出的 8 个集合，为每个集合设置 `permissions.json` 的客户端读写规则，并创建索引。
4. 将 `database/campaign.example.json` 作为单条文档导入 `ua_campaigns`。它默认 `draft`，不会对用户开放。确认租户、运营方、隐私联系渠道、公开隐私说明、授权版本、活动时间和资料后，再改为 `active`。`stock: null` 是不限量数字资料。
5. 部署 `campaign`：在该云函数目录安装锁定依赖，或选择开发者工具“上传并部署：云端安装依赖”。其 `config.json` 申请 `phonenumber.getPhoneNumber` 权限。
6. 在微信平台确认主体具备手机号组件权限、可用额度/费用与相应隐私声明；授权取得 code 后只能从服务端换号。声明中包含收集目的、手机号、标识符、使用与保留期限。客户端与活动的授权版本保持一致。
7. 部署 `scrm-dispatch`，设置超时至少 60 秒、内存按实际压测配置，创建配置中的分钟定时器。把同步函数的客户端调用权限关闭，保留受控的服务端调用。
8. 将 SCRM 适配地址、令牌和租户配置到同步函数服务端环境变量，不能写进小程序包。适配协议见接口文档。
9. 如需企业微信客服，在活动文档配置 `customerService: {corpId, url}`，按平台要求开通并关联微信客服。此按钮只打开客服会话，不代表添加企业微信好友。
10. 运行本地发布配置检查，完成下面的真实环境验收，再上传体验版和安排微信提审。

界面演示模式必须显式改成云模式。云调用错误不会自动转入演示，不会把模拟的成功结果给真实用户。

默认不包含小程序码生成。拿到 AppID 后，先用开发者工具上传体验版获取合法体验二维码。运营投放码可用微信官方接口或平台工具生成，入口为 `pages/activity/index`，可用场景 `i=<24位邀请码>`；当前 launch 解析器支持该短参数，但生成服务尚未实现。

## C. 在 BesChannels 中安排开发

需要对方明确的接入信息：测试环境凭证、租户/组织标识、联系人查询与创建/更新接口、活动记录接口、自定义字段和授权字段、分配跟进规则，以及限流/幂等机制。`/dashboard` 是后台页面入口，不能充当写入 API。

本次代码已完成微信侧事件发送与重试。后续的适配服务负责：验证发送端身份 → 按 eventId 幂等 → 将验证后手机号匹配到现有联系人或建立新联系人 → 写活动参与、咨询与授权字段 → 返回持久化接收确认 → 按实际业务分配跟进。

建议职责：产品负责人确认活动及资料；小程序开发负责原生编译、隐私与真机交互；后端负责云环境、数据权限与适配服务；SCRM 负责人确认字段、去重与跟进；测试联合完成下面的验收。当前未提供管理端实现或虚构厂商 API。

## D. 必须在真实环境验证的场景

| 场景 | 通过标准 |
| --- | --- |
| iOS / Android 普通尺寸及较小屏 | 按钮可点、文字不溢出；选择卡和模块不依赖拖动；滚动不遮挡主要操作 |
| 从首页直接开局 | 不出现企业信息或手机号表单；事件、预算、风险、行动次数正确变化 |
| AI 提示及后台恢复 | 提示按当前局面计算；退后台/离开页面后能恢复同局，过期明确重新开局 |
| 断网提交与恢复 | 不显示假成功；可以重试；同一行动记录只完成一次 |
| 完成失败局并领资料 | 失败也可领取；重复点不会重复扣份数；领取后重开小程序仍可阅读 |
| A 邀请 B，B 再邀请 C | B 首次到访计给 A，C 首次到访计给 B；自己点和重复点不新增 |
| 老访客从另一邀请卡进入 | 首触归因不改变；活动新访客与现有 SCRM 客户区分 |
| 查询个人信息 | B 无法读取 A 的领取、咨询、手机号；直接客户端数据库读写被拒绝 |
| 手机号拒绝 / 隐私拒绝 | 不提交咨询；游戏和资料仍可用；不弹出自动加友 |
| 手机号授权与重复提交 | 服务端兑换正确；客户端不能直接传手机号；只建一条咨询 |
| 不勾选可选授权 | 上游没有复盘内容、marketing=false；不能自动发营销消息 |
| SCRM 无配置 / 超时 / 错误确认 | 待同步或重试，绝不标已接收；恢复后按原 eventId 送达 |
| 撤回营销、并发同步及重试 | 撤回最终到达接收端；后续授权状态为 false；失败有待处理记录 |
| 客服入口（若启用） | 正确进入已配置客服；不把打开入口统计为加好友成功 |

当前已测试的环境与未测试项目见 [验证记录](验证记录.md)。这些项目需要真实微信与 SCRM 条件，不能仅凭本地单元测试判定发布就绪。

## E. 上线运营的必要补全

将示例品牌和隐私联系渠道替换为真实信息，明确资料版权、联系人数据保留期限和删除流程。配置服务告警、过期数据清理与人员权限；进行真实云数据库事务并发与请求额度测试。先使用少量真实流量验证，再决定是否扩大投放。

数字资料不需要邀请人数兑换。若以后引入现金、实物或有成本权益，必须另设计库存、风控与核销，不要直接复用当前内容领取作为现金发奖系统。
