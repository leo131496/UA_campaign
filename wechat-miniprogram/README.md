# 默契找茬局 · 微信原生开发交付

**[先打开手机 Demo](https://leo131496.github.io/UA_campaign/spot-preview.html?v=5)**

给客户玩的轻松小游戏：60 秒找不同 → AI 视觉提示 → 邀请好友同关挑战 → 生成双人合拍结果 → 自愿领取品牌小礼或了解服务。没有企业业务管理任务。

## 项目内容

| 内容 | 位置 |
| --- | --- |
| 客户视角、分享动机、AI 能力与 B2B 承接设计 | [产品与交互方案](docs/产品与交互方案.md) |
| 七个原生页面 | `miniprogram/pages/` |
| 找茬规则、视觉差分、区域提示、双人结果计算 | `miniprogram/lib/spot.js` |
| 与视觉分析共用图元的 SVG 插画 | `miniprogram/lib/art.js` |
| 真实模式的身份、同关邀请、结果重放及领取 | `cloudfunctions/campaign/` |
| SCRM 待同步队列、幂等、重试与撤回 | `cloudfunctions/scrm-dispatch/` |
| 接入与部署 | [接口与数据](docs/接口与数据说明.md)、[开发部署](docs/开发部署与验收.md) |
| 实际验证及待验证项 | [验证记录](docs/验证记录.md) |

默认 `demo` 模式，使用独立本地记录，不采集真实手机号。演示邀请链接携带关卡及发现顺序，第二位玩家可以在另一台手机完整体验同关与合拍结果；自报数据不用于真实发奖或新增客户统计。

云模式会使用服务端的已完成对局绑定邀请码，好友不能用客户端自报成绩替代服务端结果。微信身份、数据库和 SCRM 仍需实际部署联调。

## 导入与检查

微信开发者工具导入本目录。没有 AppID 时使用工具支持的测试项目方式，保留 `config.js` 的 `mode:'demo'`；原生编译和真机兼容仍需开发人员验证。

Node.js 18+：

```bash
npm test
npm run check
npm run check:release
```

检查不需要安装前端依赖。发布检查在当前占位 AppID、demo 模式、空 cloudEnv 下应失败。

每个云函数独立部署，依赖锁定 `wx-server-sdk@4.0.2`。新活动 ID 是 `spot-buddy-2026`；不要把历史项目游戏的会话数据当作新找茬记录。部署时导入新的活动示例，先替换品牌、租户、隐私说明与活动日期，再设为 active。

本地 AI 为实际运行的经典视觉算法；没有大模型问答、生成式插画服务或人格预测。当前也没有现金奖、真实排行榜、自动加好友或 BesChannels 管理端实现。
