# 星岛远征：从轻互动到可重复游玩的冒险

版本：v8 · 2026-11-24

[手机直接试玩](https://leo131496.github.io/UA_campaign/studio/player.html?v=8) · [配置生成](https://leo131496.github.io/UA_campaign/studio/?mode=config&v=8) · [AI 创作](https://leo131496.github.io/UA_campaign/studio/?mode=ai&v=8)

## 本次解决的问题

之前的翻牌、收集和答题具有完整活动流程，但玩家可作出的选择较少。新默认玩法增加路线选择、有限资源、角色技能、机关联动与跨关强化，构成可失败、可学习、可重玩的三关冒险。原有三个轻量模板继续适合低门槛活动。

## 手机客户旅程

无需填写资料 → 独自远征 / 邀请好友 → 探索地图 → 收集光片 → 解开星门 → 通关积分翻倍 → 三选一强化 → 下一座岛 → 自愿了解品牌。

每关默认 5 分钟；1–3 关由后台配置，玩家可提前结束。地图为 5×5，按上下左右相邻格移动，路线可回退，不是按指定顺序点击按钮。

| 决策 | 玩家需要判断什么 | 实际效果 |
| --- | --- | --- |
| 路线 | 绕路拿补给，还是穿过陷阱 | 每步 −1 能量，陷阱额外 −3，可由护盾抵挡 |
| 开关 | 先解封还是先找其他光片 | 组队关、单人第 2 / 3 关的中心光片需要开关解封 |
| 风暴 | 现在行动后会不会停在预警行 | 默认每 4 次行动落下一次，高手每 3 次；命中额外 −2，可由护盾抵挡 |
| 技能 | 现在使用，还是留到关键处 | 每人每关一次，不可无限充能或刷盾 |
| 解谜 | 转动哪个环能同时接近目标 | 联动环中 A 带动 B、B 带动 C、C 带动 A；每次 −1 能量 |
| 强化 | 下一关更需要续航、防御还是解码 | 过关后三选一，影响后续关卡 |

能量耗尽或超时，本关失败；过往积分保留。核心最后一次动作恰好用完能量并对齐时允许通关。关卡结束仅结算一次，重复动作 ID 不会重复发分。

## 单人与好友差异

| 项目 | 单人 | 组队 |
| --- | --- | --- |
| 人数 | 1 人 | 2–6 人，好友上限后台可设 0–5，不含发起人 |
| 控制 | 一人独立操作 | 所有人共享一艘飞船，按座位顺序轮流操作 |
| 光片 | 第 1 / 2 关 2 枚，第 3 关 3 枚 | 每关 3 枚 |
| 机关 | 前两关各环独立，第三关联动 | 从第一关起为联动环 |
| 风暴 | 第一关无，后两关有 | 从第一关起有 |
| 技能 | 三种技能任选一种用一次 | 按座位循环分配三类角色，每人每关一次 |
| 默认积分 | 每关 100 ×2；三关 600 | 每位有效参与者每关 200 ×2；三关每人 1,200 |

供能师恢复最多 5 能量；守护者提供 2 层护盾；解码师在核心单独转动一个环 180°，不带动邻环。2 人房间也能通关，缺少某类角色不会造成无法解题。队友可主动交接回合，消耗 1 能量，不计有效贡献；提示也不计贡献。

只有移动、转环、实际使用技能才算贡献。多人积分更高来自共同完成更复杂的目标，邀请动作本身不给积分。积分不能代表采购意向。

## 三关与营地

1. **漂流之岛**：认识地图、能量、补给与星门。单人不出现风暴或中心封印。
2. **回声遗迹**：加入封印开关与风暴预警，使用第一关获得的装备。
3. **星核之门**：单人也需要解联动机关；检验路线与资源分配。

每次通关到下一关之前，由队长选一件装备：长续航电池让以后每关初始能量 +5；星光护甲让以后每关获得 2 层护盾；解码棱镜让以后每关第一次普通转环不耗能。电池与护甲可叠加；棱镜的同类效果不叠加。已拥有棱镜后不再允许重复选择它。

地图基于已验证模板，按局标识、活动种子与章节旋转 / 镜像，补给量与机关初态变化。不是无限新玩法，也不是大模型实时生成地图。

## 后台两种设计方向

**配置生成型**：选星岛远征 → 编辑行业、品牌、标题、元素、权益 → 配置好友上限与积分 → 配置资源压力、每关时长、提示开关 → 实际试玩 → 发布演示快照。

- 入门：比标准多 8 点起始能量。
- 标准：在路线、补给、技能与机关之间作取舍。
- 高手：少 4 点能量，风暴触发更频繁。
- 提示可关闭；开启后全队每关共 2 次。
- 品牌色用于品牌识别，远征保留独立的深色冒险视觉；完整地图主题皮肤属于后续素材能力。

**AI 创作型**：输入“通用品牌的遗迹远征，最多 5 位好友，高手难度，300 秒，通关翻倍” → 示例解析成可编辑活动配置 → 预览 → 人工确认 → 共用发布流程。

当前 AI 入口使用明确标示的关键词 / 示例解析器。游戏内提示来自本地寻路和机关求解器，能分析真实状态，但没有调用大模型。正式 AI 设计：服务端接收已验证的游戏状态，按经过求解器验证的建议生成人物口吻的分级提示；模型不修改积分、奖励或回合。

## 跨行业与 SCRM 价值

冒险机制不含工业设备、销售任务或企业经营表单。品牌可替换活动标题、收集元素、权益和后续承接，适用于品牌传播、客户活动、展会或内容社群。当前冒险使用第一个品牌元素的图形作为光片外观；不会把配置的所有行业知识自动写入剧情。

客户的传播动机是邀请熟人一起规划和闯关，平台需另外提供真实邀请码与同场服务。运营关注到访 → 游戏参与 → 真实好友进入 → 自愿了解 → 身份验证与 SCRM 去重 → 销售确认。游戏本身不能保证 B2B 获客或销售转化，要用目标人群投放和品牌权益验证效果。

## 实现与接入边界

- H5 手机设计稿：上述玩法、营地、角色、规则、配置与积分演示已实现。
- 本地协作：同浏览器窗口共享房间，真实窗口控制各自回合；演示好友由体验者轮流操作，清楚标示模拟身份。
- 跨手机：尚未接入房间服务；不同手机不能加入此本地房间。生产使用服务端权威回合、状态版本、成员鉴权和断线恢复。
- 原生小程序：仓库原有 `wechat-miniprogram/` 仍是旧版找茬，新远征没有伪称已移植。新玩法核心为独立 JavaScript 模块，可供移植；还需要原生页面、接口适配、AppID 与审核。
- AI / SCRM / 奖品：未连接真实模型、BesChannels 或权益服务。后台双端发布为交互设计，不是已推送到企业系统。

生产回合协议建议：roomId、actorId、actionId、expectedRevision、actionPayload → 服务端校验身份 / 回合 / 超时 → 归约状态 → 幂等入账 → 广播新状态。客户端不能作为最终计分依据。

## 验收

自动检查覆盖标准难度下 6 组种子 × 1 / 2 / 6 人 × 3 关，共 54 次通关；轮次、相邻格、有限技能和提示、机关可解性、强化、能量与超时失败。浏览器检查覆盖三关单人、六人演示、两个真实窗口轮流协作、刷新重连、后台参数、AI 示例、320px 手机布局。

这些结果证明流程可运行，不代表已验证玩家留存、获客效果或正式联网性能。后续应通过真实客户试玩，观察首关完成率、再次游玩率、组队发起率和自愿了解率，再调整资源压力。
