# 单人与好友协作 Demo 验证

日期：2026-11-24。

## 规则验证

运行 `node --test tests/studio-model.test.cjs tests/room.test.cjs`，10 项通过。

- 多行业配置与自定义内容、分享配置编码和非法输入。
- 好友上限为 0–5 位，且不含发起人；满员、未准备、开局后新加入被拒绝。
- 三种引擎在 1 / 2 / 6 人、1–3 关条件下均可真实完成。
- 单人三关 600 分；组队三关每位有效参与者 1,200 分；不重复翻倍历史积分。
- 组队翻牌的两张卡必须由不同玩家翻开；无贡献者 0 分。
- 收集需要所有成员完成自己的目标；答题等待全员投票并检验正确多数。
- 失败关不发分、保留已通过关卡的积分；重复动作不会重复结算。
- AI 示例输入可修改好友上限、单人 / 多人积分和倍数，非法人数或积分关系被拒绝。

## 浏览器验证

运行 `node tests/studio.test.cjs`（委托 `team-studio.test.cjs`），Chromium 验证通过。

- 默认是通用行业；修改好友上限即时影响手机房间名额。
- 完整玩通单人三关和 6 人协作三关，检查逐人积分。
- 同一浏览器两个窗口实际协作：准备、共享卡牌、不同玩家配对、同步结算、刷新恢复成员身份、拒绝开局后加入。
- 不同浏览器隔离上下文打开邀请，明确显示未连接跨设备服务，不伪造加入成功。
- 自动演示好友确实执行收集动作和答题动作，三种玩法满足真实通关条件。
- 明确同意后才保存虚拟联系申请，实际客户人数和商机仍显示待接入。
- 演示发布保存好友与积分配置；v1 / v2 和恢复版本正常。
- AI 生成与修改组队规则可操作，超过 5 位好友显示错误。
- 320–1600 宽度无横向溢出；超时自动结束；文本注入不执行。

脚本语法检查通过。主要后台、手机模式页、六人房间和协作结算截图已查看。

## 范围

这是可操作的设计 Demo，未连接真实跨手机房间服务、微信原生协作运行器、大模型、SCRM 或真实积分资产。当前同步依赖同源本地存储与 Web Locks；不能把演示好友或演示积分计作真实拉新或实际权益。
