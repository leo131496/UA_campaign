# 不限行业的单人 / 好友协作活动

日期：2026-11-24。此方案扩充原来的配置生成型与 AI 创作型，两个入口共用相同的房间、关卡和积分规则。

- [后台：好友与积分配置](https://leo131496.github.io/UA_campaign/studio/?mode=config&v=7)
- [后台：AI 生成组队活动](https://leo131496.github.io/UA_campaign/studio/?mode=ai&v=7)

## 行业通用性

默认采用“好奇星球”通用主题，入口不预设工业身份。行业只影响内容包、品牌、美术与权益，不限制玩法或组队能力。

内容包包括通用、制造、软件、教育、医疗健康、金融保险、消费零售、文旅会展、专业服务、农业食品、地产家居、汽车出行能源，以及自定义行业。不是通过列完行业来实现通用：自定义名称、图案文字、题库、品牌介绍、权益和 SCRM 承接可以覆盖新的业务场景。行业专业内容仍由企业确认。

## 人数口径与参与流程

**好友上限不含发起人。最多 5 位好友，即 1 位发起人 + 5 位好友，共 6 人同时参加。**

后台可配置 0–5 位好友。0 表示只开放单人玩法；其他情况下，2 人即可开局，不需要凑齐上限。单人始终能完成完整关卡。

客户流程：选择自己玩 / 和好友玩 → 创建房间 → 自愿邀请 → 成员加入与准备 → 队长开局 → 共同闯关 → 每关结算 → 继续更难关卡 → 个人积分汇总 → 自愿了解品牌。

加入房间表示参加这场游戏，不等于自动添加微信联系人。分享入口由玩家主动操作，不自动向好友或群发消息。

## 后台增加的配置

| 配置 | 默认 | 边界与作用 |
| --- | --- | --- |
| 好友上限 | 5 位 | 0–5，硬上限不允许客户端绕过 |
| 闯关数量 | 3 关 | 可选 1–3 关，每关分别计时 |
| 每关时长 | 60 秒 | 30 / 60 / 90 秒 |
| 单人每关基础积分 | 100 分 | 正整数，上限 10,000 |
| 组队每人每关基础积分 | 200 分 | 须高于单人，上限 20,000 |
| 通关倍数 | ×2 | 可设 2–5；默认符合“通关翻倍” |
| 得分资格 | 本关有有效贡献 | 邀请、加入和挂机本身不产生积分 |
| 计分口径 | 每人分别结算 | 团队进度与个人积分分开 |

页面同时展示单人 / 组队每关收益和全部通关收益，避免用户把团队总分误解为个人积分。

## 三种玩法的难度变化

| 玩法 | 单人 | 多人 |
| --- | --- | --- |
| 记忆翻牌 | 第 1–3 关分别 2 / 3 / 4 对；自己翻完两张卡 | 根据人数与关卡配置 4–10 对；每一对的两张卡必须由不同成员翻开 |
| 灵感收集 | 每关目标 6 / 8 / 10 个；九格中 7 个目标、2 个干扰 | 每人目标 8 / 10 / 12 个；九格中 5 个目标、4 个干扰；每个人完成自己分工才通关 |
| 知识闯关 | 从 1 题逐关增加，单人选对即可 | 从 2 题起，数量不超过已配置题库；每题所有成员提交，超过半数答对才通过 |

翻牌人数系数：组队配对数 = 4 + (关卡序号 − 1) × 2 + floor((人数 − 2) / 2)。最多 6 人、3 关，因此上限 10 对 / 20 张牌。存在重复图案时同时显示编号，以保证答案明确。

收集每个人拥有自己的目标进度，其他人不能代替完成。问答在全员提交前不公开答案；不达标时先显示解释，再一起重答。翻牌与问答允许队伍完成时部分成员没有有效贡献，这类成员本关积分为 0。

## 积分计算及例子

**个人本关积分 = 本关基础分 × 通关倍数**，前提是队伍通过本关，而且本人至少有一次有效贡献。否则本关积分为 0。

有效贡献定义：翻牌成功配对的参与者；收集成功命中自己的目标；问答在团队达标的一题中选择正确答案。错点、错误答案、重复操作与仅加入房间不算有效贡献。

| 情况（默认参数） | 本关个人所得 | 三关均有效参与并通关 |
| --- | --- | --- |
| 单人通关 | 100 × 2 = 200 分 | 600 分 |
| 2–6 人协作通关 | 每人 200 × 2 = 400 分 | 每人 1,200 分 |
| 本关没通关 | 0 分 | 保留前面已通过关卡的积分 |
| 队伍通关但本人无有效贡献 | 0 分 | 不补发没有贡献关卡的积分 |

“翻倍”只作用于当前关卡基础分。不把此前累积积分再乘二，不以邀请数量额外叠加倍率，也不将团队总分再发给每个人。两人到六人的基础奖励一致，鼓励真实协作而不是凑满人数。

积分当前仅是活动演示数值，不直接兑换现金或真实权益。正式版若增加兑换，须定义每日可获积分、重复关卡获奖次数、有效期、兑换比例和库存交易，不能直接使用客户端分数。

## 房间与同步

状态：准备中 → 游戏中 → 本关结算 → 下一关 / 挑战结束。

- 成员加入、退出、移除只在准备阶段进行；队长检查人数、准备状态后开局。
- 开局固定人数、引擎、行业内容、积分规则与版本。关中不加人、不替换成员、不改奖励。
- 所有成员共享同一关卡、期限和组队状态；各自保留贡献与积分。
- 准备房间满员拒绝加入，已经开局拒绝新成员。重新加载可恢复原成员，不重复占位。
- 组队计时结束时未完成则本关失败，已获积分保留。点击退出挑战需要队长明确确认。
- 正式服务应有心跳与掉线提示、原身份重连、队长掉线处理和超时关闭。此稿不假设离开页面就是退出成员。

### 本 Demo 的实际同步能力

1. 同一页面可添加最多 5 位明确标记的“演示好友”。可开启自动协作，也可关闭并切换不同演示成员的视角操作。自动好友使用确定性规则，不冒充 AI 模型或真实客户。
2. 点击“打开同浏览器好友窗口”，可在两个独立窗口进行实际同步操作，包括准备、同一副卡牌、跨玩家配对、共同通关和重新加载恢复。通过 Web Locks 串行处理本机房间修改，避免两个窗口同时抢位或改状态。
3. 不同手机、不同浏览器或无同源存储的隔离窗口不能共享这些本地房间。页面会明确提示“演示房间不在当前浏览器”，不会制造已联机的状态。
4. GitHub Pages 仅托管静态 Demo。真实跨设备同步尚未接入，不能将当前链接当作已经上线的微信多人房间。

## 正式开发的房间服务

微信小程序和 H5 共用服务端房间与积分账本，使用微信云开发或独立实时服务均可。客户端只发动作，服务端负责成员身份、版本、可操作状态、时钟、计分与奖励。

建议能力：创建房间、加入 / 退出、准备、开局、提交动作、订阅房间增量、重连拉快照、下一关、结束、查询个人账本。

房间字段：tenantId、campaignId、releaseId、roomId、hostId、maxFriends、roster、status、level、deadline、revision、configSnapshot。

动作字段：eventId、roomId、levelId、actorId、expectedRevision、actionType、payload。可信 actorId 来自服务端会话，不接受前端传任意玩家身份。乱序动作检查版本，同一 eventId 幂等；配对、投票和满员检查在原子事务内完成。

账本去重键：tenantId + campaignId + roomId + levelId + participantId + rewardType。通关写入账本与状态迁移应处于同一事务。客户端超时重发、刷新、重复点击不能重复获奖。

## AI 创作型的扩展

输入示例：“不限行业的品牌活动，单人轻松翻牌，最多添加 3 位好友；单人 50 分，组队每人 150 分，通关翻倍，三关逐步变难。”

AI 应输出行业内容、玩法、好友上限、单人 / 多人难度曲线、基础积分、通关倍数、有效贡献定义和房间状态方案。后台展示积分预览与待确认项，仍由企业确认后发布。

当前设计稿解析上述受支持字段，能识别好友人数与积分修改，超过 5 位会给出明确错误。未接入真实大模型、图片生成或企业知识库。

## SCRM 的变化

新增 room_created、room_joined、level_started、level_cleared、challenge_finished 与服务端 points_awarded 等事件。邀请者、实际加入者、活动版本及渠道分别归因；演示好友不作为真实客户或新增用户。

“玩过”“组队过”“有积分”都是活动行为，不等于有效线索。用户明确授权申请后才关联联系方式、兴趣主题和 SCRM；按历史身份去重，再由企业标准确认客户与商机。

## 范围

本轮扩充的是双方案可交互设计 Demo。包含三种单人 / 多人玩法、人数限制、逐关难度、个人积分账本、同浏览器窗口同步、后台配置、AI 示例解析、H5 演示版本发布。真实微信多人服务、企业 AI、SCRM 与积分资产系统仍是后续接入项。原有 `wechat-miniprogram/` 继续作为历史原型，未声称已具备新协作引擎。
